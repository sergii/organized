# Outcomes

Outcomes record what actually changed after an action or session.

Do not create synthetic outcomes to make a workflow look validated. A planned action is not an outcome, and an expected benefit is not evidence that the benefit occurred.

Useful outcome fields may include:

- time spent;
- usable space gained;
- items removed or resolved;
- number of unresolved decisions;
- whether a working zone became available;
- whether retrieval became easier;
- whether the problem returned later;
- participant-reported confidence, stress, or friction.

Approximate measurements are acceptable when marked as approximate. False precision is worse than honest qualitative evidence.

Outcome records use `ORG-OUT-*` IDs and should follow `schemas/outcome.schema.yml`.
