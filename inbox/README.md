# Inbox

The inbox is the cheapest possible capture layer.

Do not try to author polished knowledge while cleaning, moving, sorting, reading, or interviewing someone. Capture the raw signal first and curate it later.

Useful inbox entries include:

- a voice note from a real session;
- a surprising result;
- a repeated question;
- a quote or claim from a source;
- a photo reference with a short note;
- a failed recommendation;
- a conflict between two approaches;
- a possible principle that still needs testing.

A good raw capture often has only four parts:

```text
context
what happened
what surprised me
what should be checked later
```

Example:

```text
Context: small room with almost no free floor area.
What happened: I considered starting with papers and receipts.
Surprise: this category may require many decisions while freeing almost no working space.
Check later: compare paper-first sorting with high-volume obvious exits.
```

## Promotion path

```text
inbox
  ↓
observation / question / source claim
  ↓
compare with existing knowledge
  ↓
knowledge / gap / conflict
```

Inbox material is disposable. Once it has been normalized and linked, the raw note does not need to become permanent canonical knowledge.
